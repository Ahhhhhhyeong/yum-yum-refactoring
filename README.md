# YUM-YUM 리팩토링

‘오늘의 냠냠’은 하루 식단을 기록하고 목표 대비 영양 섭취 현황을 확인하는 식단 관리 서비스입니다.
이 저장소에서는 기존 React 프로젝트를 **React 프론트엔드와 Spring Boot 백엔드로 분리**하는 리팩토링을 진행합니다.

## 현재 구조

- `yum-yum/`: React + Vite로 구현된 프론트엔드
- `yum-yum-backend/`: Spring Boot + Gradle로 생성한 백엔드 기본 프로젝트
- `.github/`: GitHub 문서 템플릿
- React에서 Firebase Authentication, Firestore 및 AI 기능을 직접 호출하여 인증과 데이터 처리를 수행합니다.
- Spring 백엔드의 기본 구성을 생성했으며, 기존 기능은 단계적으로 이전할 예정입니다.

## 리팩토링 목적

- 화면과 사용자 상호작용은 React에서, 인증·비즈니스 로직·데이터 접근은 백엔드에서 담당하도록 역할을 분리합니다.
- 프론트엔드의 Firebase 직접 의존을 줄이고, API를 통해 서버와 통신하는 구조로 전환합니다.
- 기능별 책임을 명확히 하여 유지보수, 테스트 및 기능 확장이 쉬운 구조를 만듭니다.

## 진행 계획

1. **기존 기능 분석**: 회원 인증, 식단·수분·체중 기록, 목표 관리, 분석 리포트 및 AI 기능의 Firebase 사용 흐름과 데이터 구조를 정리합니다.
2. **백엔드 설계 및 구성**: 생성한 Spring Boot 프로젝트를 기반으로 데이터 모델과 REST API, 인증 방식 및 데이터 저장 방식을 설계합니다.
3. **기능별 이전**: 인증과 주요 기록 기능부터 백엔드로 옮기고, 분석 및 AI 기능을 단계적으로 이전합니다. 기존 데이터의 이전 필요성과 방법도 함께 검토합니다.
4. **프론트엔드 연동**: React의 Firebase 직접 호출을 백엔드 API 호출로 교체하고, 로딩·오류·인증 상태 처리를 정리합니다.
5. **검증 및 문서화**: 기존 기능이 동일하게 동작하는지 확인하고, API 명세와 프론트엔드·백엔드 실행 방법을 문서화합니다.

목표 구조는 `React → Spring Boot API → 데이터 저장소 및 외부 서비스`이며, 저장소와 인증 방식은 설계 단계에서 결정합니다.

## 프론트엔드 실행

저장소 루트에서 다음 명령을 실행합니다.

```bash
cd yum-yum
npm install
npm run dev
```

실행 전 기존 Firebase 연동에 필요한 환경 변수를 설정해주세요. 개발 시 유의 사항은 [프론트엔드 README](yum-yum/README.md)를 확인하세요.

## 백엔드 실행

```bash
cd yum-yum-backend
./gradlew bootRun
```

백엔드 설정과 빌드 방법은 [백엔드 README](yum-yum-backend/README.md)를 확인하세요.
